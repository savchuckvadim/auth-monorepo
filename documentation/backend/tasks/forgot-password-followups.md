# Forgot / Reset / Change Password — follow-ups

## 1. Нет rate-limit на `forgot-password`

Любой может постить бесконечно — увеличит нагрузку на SMTP и bcrypt (последний специально
делаем даже на несуществующих email для timing-oracle защиты).

План: добавить `@Throttle({ ttl: 60_000, limit: 3 })` как по IP, так и по email (через
кастомный guard с Redis-счётчиком, ключи `forgot:ip:<ip>` и `forgot:email:<email>`).

## 2. Нет rate-limit на `reset-password`

Bruteforce токена теоретически возможен (хотя 32 байта энтропии — это 2^256; практически
нереально), но всё равно стоит ограничить 10 запросов/минуту с одного IP.

## 3. Очистка stale токенов не автоматизирована

Реализован `PasswordResetRepository.removeStaleTokens`, но нигде не вызывается. Надо:

- Добавить в `TokenCleanupService` (или сделать отдельный `PasswordResetCleanupService`)
  ежедневный cron, который пройдёт и удалит `expiresAt < now` + `consumedAt != null`.
- Использовать тот же Redis-lock, что и для refresh-токенов.

## 4. Email не локализован

Текст письма зашит на русском. Когда появится i18n — вынести в `i18n/auth/password-reset.*`
и выбирать язык по `Accept-Language` / настройке пользователя.

## 5. Нет уведомления о смене пароля

После `reset-password` / `change-password` хорошо бы слать дополнительное письмо "пароль был
успешно изменён, если это не вы — свяжитесь с поддержкой". Сейчас не реализовано.

## 6. Password history не ведётся

Пользователь может поставить текущий пароль заново через reset (а в change-password мы
блокируем только совпадение с текущим). Для параноидальных политик нужно хранить последние
N хешей в отдельной таблице.

## 7. Reset-токен идёт в query

Ссылка вида `/auth/reset-password?token=...`. Плюсы: удобно, любой клиент откроет. Минусы:
token попадает в HTTP Referer / логи фронт-прокси. План: после открытия страницы на фронте
немедленно вырезать токен из URL (`history.replaceState`) + не логировать query на CDN.

## 8. Mobile deep-link

Ссылка ведёт на web (`CLIENT_URL`). Для полноценного UX на mobile хорошо бы сделать universal
link / app scheme (`sociopath://auth/reset-password?token=...`) и обработку в RN. Сейчас
пользователь на мобильном кликает ссылку → открывается браузер → там reset. Работает,
но неидеально.

## 9. Change-password ревокает все другие сессии — без предупреждения

UX: перед кнопкой "Сменить пароль" хорошо бы чек-бокс "Выйти со всех других устройств"
(default: on). Сейчас всегда on — даже если юзер просто хочет обновить пароль "на всякий случай"
и не трогать сессии. Дискуссионно; пока оставлено как есть ради безопасности.
