# Задачи Backend

## Приоритетные задачи

### 1. Микросервисная архитектура на основе Kafka

**Назначение**: Применить микросервисную архитектуру на основе Apache Kafka, вынести аутентификацию в отдельный микросервис и организовать асинхронную коммуникацию между сервисами.

**Подробное описание**: См. [Детальное описание задачи](./microservices-architecture.md)

**Краткое описание**: Создать отдельный Auth Service (NestJS), настроить Kafka для коммуникации между сервисами, обновить API Gateway для работы через Kafka, организовать публикацию событий, пошаговая инструкция для джуна/джуниора.

**Важно**: Большая архитектурная задача, требует понимания микросервисов и Kafka

**Приоритет**: Высокий - архитектурное улучшение

---

### 2. OAuth авторизация и CAPTCHA

**Назначение**: Реализовать backend поддержку OAuth авторизации через Yandex, Google, Telegram и интеграцию CAPTCHA для защиты от ботов.

**Подробное описание**: См. [Детальное описание задачи](./oauth-captcha.md)

**Краткое описание**: OAuth сервисы для Yandex/Google/Telegram, модель OAuthAccount, обработка OAuth callback, CAPTCHA сервисы (reCAPTCHA, hCaptcha, Turnstile), CAPTCHA guard для защиты endpoints.

**Связанная frontend задача**: См. [Frontend задача по OAuth и CAPTCHA](../../frontend/tasks/oauth-captcha.md)

**Приоритет**: Высокий - безопасность и удобство

---

### 3. Функционал групп

**Назначение**: Создать backend функционал для групп (публичные и закрытые) по аналогии с ВКонтакте. Группа выглядит как профиль с постами, может иметь групповой чат, поддерживает теги и фильтрацию. После переезда на LiveKit расширить функционал звонков до групповых.

**Подробное описание**: См. [Детальное описание задачи](./groups.md)

**Краткое описание**: Создать модели Group и GroupMember, API endpoints для групп, интеграция с постами и чатами, групповые звонки через LiveKit.

**Важно**: Выполнять **после** миграции на LiveKit

**Связанная frontend задача**: См. [Frontend задача по группам](../../frontend/tasks/groups.md)

---

### 4. Улучшение endpoint ленты новостей

**Назначение**: Улучшить существующий endpoint `GET /api/posts/feed` для поддержки фильтрации, сортировки и оптимизации загрузки данных.

**Подробное описание**: См. [Детальное описание задачи](./news-feed-endpoint.md)

**Краткое описание**: Добавить фильтрацию (по типу поста, авторам, дате), сортировку (по дате, популярности), оптимизацию запросов и кэширование.

**Связанная frontend задача**: См. [Frontend задача по ленте новостей](../../frontend/tasks/news-module.md)

---

### 5. История аватаров и hero изображений

**Назначение**: Реализовать хранение истории аватаров и hero изображений пользователя. Пользователь может иметь множество аватаров и hero изображений, которые сохраняются в истории.

**Подробное описание**: См. [Детальное описание задачи](./profile-avatar-history.md)

**Краткое описание**: Создать модели для истории аватаров и hero, API endpoints для получения и восстановления из истории, автоматическая очистка старых записей.

**Связанная frontend задача**: См. [Frontend задача по редактированию профиля](../../frontend/tasks/edit-profile.md)

---

### 6. Уведомления подписчиков об изменениях профиля

**Назначение**: Реализовать функционал уведомления подписчиков об изменениях профиля. При изменении профиля (если включен чекбокс) создается пост на стене автора.

**Подробное описание**: См. [Детальное описание задачи](./profile-update-notifications.md)

**Краткое описание**: Добавить поле `notifyFollowers` в UpdateProfileDto, создание поста при изменении профиля, определение типов изменений.

**Связанная frontend задача**: См. [Frontend задача по редактированию профиля](../../frontend/tasks/edit-profile.md)

---

### 7. Сквозное шифрование для чатов и звонков

**Назначение**: Реализовать backend поддержку сквозного шифрования (End-to-End Encryption, E2EE) для чатов и звонков по типу протокола Signal. Обеспечить инфраструктуру для обмена ключами и поддержки зашифрованных сообщений.

**Подробное описание**: См. [Детальное описание задачи](./end-to-end-encryption.md)

**Краткое описание**: Создать модуль encryption для управления ключами, prekeys и one-time prekeys, API endpoints для обмена ключами, поддержка зашифрованных сообщений.

**Связанная frontend задача**: См. [Frontend задача по сквозному шифрованию](../../frontend/tasks/end-to-end-encryption.md)

---

### 8. Секретный режим в чате

**Назначение**: Реализовать backend поддержку для секретного режима в чатах. Backend не хранит содержимое секретных сообщений, но обеспечивает обмен ключами Signal Protocol, метаданные сообщений и уведомления.

**Подробное описание**: См. [Детальное описание задачи](./secret-chat-mode.md)

**Краткое описание**: Создать модели для хранения prekeys и метаданных секретных сообщений, API endpoints для обмена ключами и метаданными, WebSocket события для уведомлений.

**Важно**: Выполнять **после** задачи [Сквозное шифрование для чатов и звонков](#5-сквозное-шифрование-для-чатов-и-звонков)

**Связанная frontend задача**: См. [Frontend задача по секретному режиму](../../frontend/tasks/secret-chat-mode.md)

---

### 9. Пагинация списка пользователей

**Назначение**: Добавить поддержку пагинации для endpoint получения списка пользователей. Реализовать cursor-based пагинацию для эффективной загрузки больших списков.

**Подробное описание**: См. [Детальное описание задачи](./users-pagination.md)

**Краткое описание**: Добавить cursor-based пагинацию в `GET /api/user`, поддержка параметров `cursor`, `limit`, `search`, возврат `nextCursor` и `hasNext`.

**Связанная frontend задача**: См. [Frontend задача по странице People](../../frontend/tasks/people-page.md)

---

### 10. AI Агенты (Джарвисы)

**Назначение**: Реализовать backend функционал для AI агентов - персональных AI ассистентов с поддержкой RAG, интеграцией с разными LLM (Ollama, GigaChat, OpenAI), голосовым общением через LiveKit и выполнением заданий в соцсети.

**Подробное описание**: См. [Детальное описание задачи](./ai-agents.md)

**Краткое описание**: LangChain для обработки, RAG с векторной БД, интеграция с Ollama/GigaChat/OpenAI, обработка текстовых и голосовых сообщений, выполнение заданий (подписка, лайк, пост, сообщение), LiveKit интеграция для голосовых звонков.

**Важно**: Выполнять **после** миграции на LiveKit

**Связанная frontend задача**: См. [Frontend задача по AI агентам](../../frontend/tasks/ai-agents.md)

---

### 11. API для фильтрации и поиска

**Назначение**: Реализовать backend API для фильтрации и поиска в ленте постов, сообщениях и списке пользователей с поддержкой cursor-based пагинации.

**Подробное описание**: См. [Детальное описание задачи](./filter-search-api.md)

**Краткое описание**: Фильтрация и поиск для постов (тип, автор, дата), чатов (тип, непрочитанные), пользователей (отношения, онлайн), интеграция с пагинацией, оптимизация запросов (индексы, кэширование).

**Связанная frontend задача**: См. [Frontend задача по Filter и Search](../../frontend/tasks/filter-search-components.md)

## Примечания

- Все задачи должны быть выполнены в соответствии с архитектурой NestJS
- Использовать Prisma для работы с базой данных
- Следовать принципам REST API
- Если задача связана с frontend, проверять наличие соответствующей frontend задачи в `documentation/frontend/tasks/`
