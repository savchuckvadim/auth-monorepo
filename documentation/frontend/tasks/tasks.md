# Задачи Frontend

## Приоритетные задачи

### 1. Создание дизайн-системы

**Назначение**: Создать централизованную дизайн-систему для обеспечения единообразия UI компонентов и стилей во всем приложении. Дизайн-система должна скрывать внутренние детали компонентов (например, CardContent, CardHeader) и предоставлять простой высокоуровневый API для переиспользования.

**Подробное описание**: См. [Детальное описание задачи](./design-system.md)

**Краткое описание**:
- [ ] Создать новый пакет `packages/design-system/` в монорепо
- [ ] Мигрировать композитные компоненты (Avatar, UserCard, MessageCard и т.д.)
- [ ] Создать новые компоненты (FormField с иконками, Filter, Grid, Pagination)
- [ ] Определить дизайн-токены (цвета, типографика, spacing, shadows)
- [ ] Создать систему тем (light/dark)
- [ ] Обеспечить правильную инкапсуляцию (скрыть внутренние детали)
- [ ] Настроить Public API (экспортировать только высокоуровневые компоненты)

**Архитектура**:
- **Примитивы** остаются в `@workspace/ui` (Button, Input, Card и т.д.)
- **Композиты** переносятся в `@workspace/design-system` (UserCard, MessageCard и т.д.)
- **Паттерны** создаются в `@workspace/design-system` (FormField с иконками, Filter и т.д.)

**Компоненты для миграции/создания**:
- Avatar (с online/offline индикатором)
- UserCard
- MessageCard
- FormField (с поддержкой иконок)
- Filter
- Grid
- Pagination
- StatusIndicator (online/offline)
- И другие переиспользуемые компоненты

**Файлы для работы**:
- `packages/ui/` - примитивные компоненты (остаются там)
- `apps/front/modules/shared/ui/` - компоненты для миграции
- `apps/front/modules/entities/*/ui/` - компоненты для миграции
- `packages/theme/` - текущая тема (интегрировать)
