# Страницы приложения

## Обзор

Страницы находятся в `app/` директории (Next.js App Router). Каждая страница - это точка входа, которая композирует widgets, features и entities.

## Структура страниц

```
app/
├── auth/              # Страницы аутентификации
│   ├── login/        # Вход
│   ├── register/     # Регистрация
│   ├── confirm/      # Подтверждение email
│   └── start/        # Стартовая страница
├── network/          # Защищенные страницы (требуют авторизации)
│   ├── me/           # Профиль текущего пользователя
│   ├── people/       # Список пользователей
│   ├── people/[userId]/ # Профиль пользователя
│   ├── chats/        # Список чатов
│   ├── chats/[chatId]/ # Переписка
│   └── calls/        # Страница видеозвонков (тестовая)
└── layout.tsx        # Корневой layout
```

## Страницы аутентификации

### `/auth/login` - Вход в систему

**Файл**: `app/auth/login/page.tsx`

**Описание**: Страница входа в систему

**Компоненты**:
- `LoginFormWrapper` → `modules/processes/auth/ui/LoginForm/LoginForm`

**Логика**:
1. Пользователь вводит email и password
2. Вызывается `loginThunk` из `useAuth()`
3. При успехе → редирект на `/network/me` или `/auth/confirm`
4. При ошибке → отображение ошибки

**Защита**: Middleware редиректит авторизованных пользователей на `/network/me`

---

### `/auth/register` - Регистрация

**Файл**: `app/auth/register/page.tsx`

**Описание**: Страница регистрации нового пользователя

**Компоненты**:
- `RegistrationFormWrapper` → `modules/processes/auth/ui/RegistredForm/RegistredForm`

**Логика**:
1. Пользователь заполняет форму (name, email, password, confirmPassword)
2. Вызывается `registerThunk` из `useAuth()`
3. При успехе → редирект на `/auth/confirm`
4. Backend отправляет email с ссылкой активации

**Защита**: Middleware редиректит авторизованных пользователей на `/network/me`

---

### `/auth/confirm` - Подтверждение email

**Файл**: `app/auth/confirm/page.tsx`

**Описание**: Страница подтверждения email аккаунта

**Логика**:
1. Пользователь переходит по ссылке из email
2. Backend активирует аккаунт по токену из URL
3. После активации пользователь может войти

**Защита**: Доступна без авторизации (для активации)

---

## Защищенные страницы (требуют авторизации)

Все страницы в `/network/*` защищены middleware и требуют наличия токена.

### Layout для `/network/*`

**Файл**: `app/network/layout.tsx`

**Описание**: Общий layout для всех страниц сети

**Компоненты**:
- `Header` - шапка сайта
- `Navigation` - боковая навигация
- `GlobalCallProvider` - провайдер для звонков
- `CallWrapperWidget` - обертка для звонков

**Логика**:
- Проверяет наличие `currentUser` через `useAuth()`
- Если пользователь не загружен → показывает `LoadingScreen`
- Отображает Header и Navigation для всех страниц сети

### `/network/chats/[chatId]` - Переписка

**Файл**: `app/network/chats/[chatId]/page.tsx`

**Описание**: Страница переписки в конкретном чате

**Параметры**:
- `chatId` - ID чата из URL

**Компоненты**:

- `ChatInputWidget` - виджет ввода сообщения

**Функционал**:
- Отображение истории сообщений
- Отправка сообщений

- Приватные чаты с **Signal E2EE** (`encryptionMode: SIGNAL`) — см. [Signal E2EE](./encryption/signal-e2ee-messenger.md)

---

### `/network/calls` - Видеозвонки (тестовая страница)

**Файл**: `app/network/calls/page.tsx`

**Описание**: Тестовая страница для проверки работы LiveKit

**Компоненты**:
- `VideoCall` - компонент видеозвонка из `modules/features/call/ui/LiveKitTest`
- `useLivekitToken` - хук для получения токена LiveKit

**Логика**:
1. Получает токен LiveKit через API
2. Отображает компонент видеозвонка
3. Подключается к комнате `room1`

**Важно**: Это тестовая страница для проверки работы LiveKit. В будущем звонки будут интегрированы в чаты.

## Middleware и защита роутов

Все роуты защищены через Next.js Middleware (`middleware.ts`):

- `/auth/*` - доступны без авторизации (кроме случаев, когда пользователь уже авторизован)
- `/network/*` - требуют авторизации (редирект на `/auth/login` если нет токена)
- `/` - редирект на `/auth/login` или `/network/me` в зависимости от авторизации

Подробнее см. [Документацию по Auth](./auth.md#nextjs-middleware)
